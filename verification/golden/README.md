# Golden vectors

Generated by `GoldenGen.java` from **kafka-clients 4.1.0**, the same Kafka version that
`protocol_codegen` pins. The generator is deterministic (fixed seed).

Regenerate (Java 17 + Maven):

    cd verification/golden && mvn -q compile exec:java -Dexec.args="$(pwd)/vectors"

- `messages.jsonl`: per (API key, request/response, version): the default message, 3 random
  messages, and 4 mutations of each, with Java's decode outcome and value (patched
  JsonConverter output).
- `headers.jsonl`: Java's request/response header version for every API version.
- `records.jsonl`: v0/v1/v2 record sets (plain, idempotent, transactional, concatenated) and
  mutations, with Java's decode outcome.

Consumed by `spec/tests/golden_*.rs`. Bumping the Kafka version means bumping it here and in
`protocol_codegen/src/main.rs` together.

Notes:

- Total vector size is about 3 MB, so `MUTATIONS_PER_VECTOR` stays at 4.
- Random generation of unsigned fields (for example uint16 `port`, held in a Java `int`) retries
  with an in-range value when Java's setter rejects the first draw. This is a generator-side
  fix; it does not change what Java's serializers emit.
- `Class.getMethods()` order varies between JVM runs, so field getters are sorted by name before
  seeded random generation; without this the vectors were not reproducible.
